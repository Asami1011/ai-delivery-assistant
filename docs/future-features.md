# Future Features

## 基本方針

AI Delivery Assistant は「開発支援・業務改善支援プラットフォーム」として成長させる。

開発ライフサイクル全体を支援することを優先し、関連性の低い機能は別プロダクトとして扱う。

---

# 採用予定機能

## Priority S

### AI議事録

概要:

* 会議内容の要約
* 議事録生成
* アクションアイテム抽出
* 要件定義への変換

将来的な連携:

会議
↓
議事録
↓
要件定義
↓
タスク分解
↓
GitHub Issue

採用理由:

現在のプロダクトコンセプトとの親和性が非常に高い。

優先度:

高

想定Phase:

v3

---

## Priority A

### AIナレッジ検索

概要:

* 過去の要件定義検索
* 過去のレビュー検索
* 過去の業務改善提案検索
* プロジェクト横断検索

技術候補:

* Vector DB
* RAG
* Embedding

採用理由:

過去の成果物を再利用できるようになる。

優先度:

高

想定Phase:

v4

---

## Priority A

### GitHub連携

概要:

* Issue作成
* PRレビュー
* Repository解析

採用理由:

現在の開発支援機能との親和性が高い。

優先度:

高

想定Phase:

v2

---

## Priority A

### Jira / Backlog / Notion連携

概要:

* タスク管理ツールとの連携
* 要件定義からタスク作成
* チーム利用支援

採用理由:

実務利用価値が高い。

優先度:

高

想定Phase:

v5

---

# 採用保留機能

## Priority C

### AIコーディング

例:

* Cursor
* Claude Code
* GitHub Copilot

理由:

競合が非常に強い。

AI Delivery Assistant はコード生成ではなく、開発プロセス支援に集中する。

保留。

---

# 別プロダクト候補

## AI営業支援

例:

* 顧客リスト作成
* メール作成
* 営業分析

理由:

現在のプロダクトとの関連性が低い。

別サービスとして検討する。

---

## AI学習サービス

例:

* TOEIC
* 英会話
* 資格勉強

理由:

現在のプロダクトコンセプトと異なる。

ユーザー層も異なるため別プロダクトとして扱う。
