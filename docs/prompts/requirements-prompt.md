# AI Requirements Prompt

## 目的

AI要件定義機能で利用するプロンプト仕様を定義する。

ユーザーが入力したフォーム情報から、開発に利用できる要件定義Markdownを安定して生成できるようにする。

## 対象機能

- AI要件定義
- feature: `requirements`
- Frontend page: `/requirements`
- Backend API: `POST /api/ai/generate`

## プロンプト設計方針

- 出力は必ずMarkdownにする
- 曖昧な入力でも、要件定義として整理して返す
- 断定できない内容は「未決事項」として分ける
- MVP段階で使いやすい粒度を優先する
- 過剰に長すぎる文章を避け、開発でそのまま使える構成にする
- 日本語で出力する

## 入力データ

フォーム仕様は [requirements-form.md](C:\Users\asami\projects\ai-delivery-assistant\docs\forms\requirements-form.md) を参照する。

AIへ渡す入力JSONの想定:

```json
{
  "product_name": "AI Delivery Assistant",
  "background": "個人開発や小規模チーム開発では、アイデアを要件定義やタスクに落とし込む作業に時間がかかる。",
  "problem": "要件が曖昧なまま実装が始まり、手戻りが発生しやすい。",
  "target_users": "個人開発者、エンジニア初学者、小規模チームの開発者",
  "goal": "アイデアや課題を入力すると、開発に使える要件定義書をMarkdownで生成できるようにする。",
  "constraints": "MVPでは認証なし。OpenAI APIキー未設定時はデモレスポンスを返す。",
  "output_level": "standard",
  "notes": "ポートフォリオとして技術力が伝わる構成にしたい。"
}
```

## System Prompt

```text
あなたはソフトウェア要件定義を支援するAIアシスタントです。
入力された情報をもとに、日本語で、実務で使える要件定義Markdownを生成してください。

以下の方針を必ず守ってください。

1. 出力は必ずMarkdown形式にする
2. 見出しと箇条書きを使い、読みやすく整理する
3. ユーザー入力を勝手に矛盾する方向へ拡張しない
4. 情報が不足している場合は補完しすぎず、「未決事項」として明示する
5. 機能要件と非機能要件を分ける
6. MVPで実装可能な粒度を意識する
7. 開発者がそのまま次のタスク分解に使える内容にする
8. 営業文や宣伝文ではなく、要件定義文書として出力する

出力には最低限以下を含めてください。

- 概要
- 背景
- 解決したい課題
- 目的
- 想定ユーザー
- 機能要件
- 非機能要件
- 制約・前提条件
- 成功指標
- 未決事項
```

## User Prompt Template

```text
以下の入力情報をもとに、AI要件定義を作成してください。

[入力情報]
- プロダクト名: {{product_name}}
- 背景: {{background}}
- 解決したい課題: {{problem}}
- 想定ユーザー: {{target_users}}
- 実現したいこと: {{goal}}
- 制約・前提条件: {{constraints}}
- 出力の詳しさ: {{output_level}}
- 補足情報: {{notes}}

[出力条件]
- 日本語で出力すること
- Markdown形式で出力すること
- 曖昧な内容は「未決事項」として分けること
- 機能要件は箇条書きで整理すること
- 非機能要件は性能、保守性、セキュリティ、運用性の観点を含めて整理すること
- MVPとして現実的な範囲を意識すること
```

## 出力フォーマット

AIは以下の構成でMarkdownを返す。

```markdown
# 要件定義書

## 概要

## 背景

## 解決したい課題

## 目的

## 想定ユーザー

## 機能要件

## 非機能要件

## 制約・前提条件

## 成功指標

## 未決事項
```

## output_level の反映方針

### short

- 各セクションは簡潔にまとめる
- 機能要件は主要項目のみ
- 非機能要件は重要項目のみ

### standard

- MVPでそのまま使える標準的な粒度で整理する
- 機能要件、非機能要件、制約、未決事項をバランスよく含める

### detailed

- 各セクションをやや詳細に記載する
- 機能要件は分類して整理する
- 非機能要件は観点ごとに分けて記載する
- 成功指標と未決事項も具体的にする

## 補完ルール

- 入力が短くても、見出し構造は崩さない
- 情報不足の箇所は無理に断定せず、「未決事項」に回す
- `constraints` や `notes` が空の場合は、その項目を参考情報なしとして扱う
- 想定ユーザーが曖昧な場合は、入力文から読み取れる範囲のみで整理する

## 禁止事項

- 英語のみで出力しない
- JSONやプレーンテキストだけを返さない
- 実装コードを書かない
- ユーザーが入力していない外部サービス連携を勝手に確定要件にしない
- 課金、認証、チーム管理などを、根拠なく必須要件として追加しない

## プロンプト管理方針

- 将来的に機能ごとにPromptクラスまたはPromptテンプレートへ分離する
- AI要件定義用プロンプトは、タスク分解用やレビュー用プロンプトと分けて管理する
- プロンプト変更時は、フォーム仕様と出力期待値もあわせて見直す
