# Requirements

## 概要

ai-delivery-assistant は、AIを活用して要件定義、タスク分解、コードレビュー、業務改善提案を支援するWebアプリケーションです。

初期版では、個人開発者がポートフォリオや学習目的で利用できるMVPを作成します。将来的にはSaaS化を想定し、拡張可能な構成を目指します。

## 目的

- ポートフォリオとして技術力を示す
- AI活用、Web開発、設計、運用の技術力を維持する
- 将来的なSaaS化に向けた土台を作る

## ユースケース

### UC-01: アイデアから要件を作成する

ユーザーは、作りたいサービスや解決したい課題を入力します。

システムは、入力内容をもとに以下を生成します。

- プロダクト概要
- 背景
- 課題
- 目的
- 対象ユーザー
- 機能要件
- 非機能要件
- 制約
- 成功指標

### UC-02: 要件からタスクを作成する

ユーザーは、要件定義の内容を入力します。

システムは、開発タスクを以下の観点で分解します。

- タスク名
- タスク概要
- 優先度
- 依存関係
- 完了条件
- 想定工数
- 担当領域
- マイルストーン

### UC-03: タスク分解結果からGitHub Issue形式を作成する

ユーザーは、AIタスク分解の生成結果をもとに、GitHub Issueとして登録しやすいMarkdownを生成します。

システムは、各タスクに対して以下を含むIssue形式のMarkdownを生成します。

- Issueタイトル
- 概要
- 背景
- 対応内容
- 完了条件
- 優先度
- 工数見積
- 関連タスク

### UC-04: コードや設計をレビューする

ユーザーは、コード、設計メモ、変更内容を入力します。

システムは、以下の観点でレビュー結果を生成します。

- バグの可能性
- 可読性
- 保守性
- セキュリティ
- パフォーマンス
- テスト不足
- 改善提案

### UC-05: 業務改善案を作成する

ユーザーは、現在の業務内容、課題、制約を入力します。

システムは、以下を生成します。

- 業務フローの整理
- ボトルネック
- 改善案
- 自動化候補
- 期待効果
- 実行ステップ
- リスクと注意点

## 機能要件

### FR-01: AI要件定義

ユーザーが入力したアイデアや課題から、要件定義ドキュメントを生成できること。

入力項目:

- プロダクト名
- 背景
- 解決したい課題
- 想定ユーザー
- 実現したいこと
- 制約や前提

出力項目:

- 概要
- 背景
- 目的
- 対象ユーザー
- 機能要件
- 非機能要件
- 制約
- 成功指標

### FR-02: AIタスク分解

要件定義の内容から、実装可能なタスク一覧を生成できること。

入力項目:

- 要件定義テキスト
- 優先したい観点
- 想定期間
- 開発体制

出力項目:

- タスク一覧
- 優先度
- 依存関係
- 完了条件
- 想定工数
- マイルストーン

### FR-03: 工数見積機能

AIタスク分解時に、各タスクの工数見積と優先順位を生成できること。

工数見積では、以下を出力できること。

- 想定工数
- 見積理由
- 実装難易度
- 前提条件
- 依存タスク

優先順位では、以下を出力できること。

- 優先度
- 優先度の理由
- MVPでの必要性
- 後回しにできるかどうか

### FR-04: GitHub Issue生成機能

AIタスク分解の結果から、GitHub Issue形式のMarkdownを生成できること。

Issue形式のMarkdownには、以下を含めること。

- タイトル
- 概要
- 背景
- 対応内容
- 完了条件
- 優先度
- 工数見積
- 関連タスク

将来的には、GitHub APIと連携してIssueを自動作成できる構成を検討する。

### FR-05: AIレビュア

コードや設計内容に対して、レビューコメントを生成できること。

入力項目:

- レビュー対象テキスト
- 使用技術
- レビュー観点
- 補足情報

出力項目:

- 指摘内容
- 重要度
- 理由
- 修正案
- テスト観点

### FR-06: AI業務改善提案

業務内容や課題から、改善提案を生成できること。

入力項目:

- 業務概要
- 現在の課題
- 関係者
- 制約
- 改善したい指標

出力項目:

- 現状整理
- 課題分析
- 改善案
- 自動化候補
- 優先順位
- 期待効果
- 実行ステップ

### FR-07: Markdown出力

AIが生成した結果をMarkdown形式で表示できること。

将来的にはコピー、保存、エクスポートに対応すること。

### FR-08: 履歴管理

ユーザーが過去に生成した結果を確認できること。

初期MVPでは任意機能とし、Phase 2以降で実装する。

## 非機能要件

### NFR-01: ユーザビリティ

ユーザーが迷わず各AI機能を使える画面構成にすること。

- 入力項目を分かりやすく配置する
- 生成中の状態を表示する
- エラー時に再試行しやすくする
- 出力結果を読みやすいMarkdown表示にする

### NFR-02: 保守性

機能ごとのプロンプト、画面、API処理を分離し、変更しやすい構成にすること。

### NFR-03: 拡張性

将来的なSaaS化に備え、以下を追加しやすい設計にすること。

- ユーザー認証
- ワークスペース
- プロジェクト
- 履歴保存
- 課金
- 外部ツール連携
- GitHub API連携

### NFR-04: セキュリティ

OpenAI APIキーやユーザー入力を安全に扱うこと。

- APIキーをクライアントに露出しない
- 秘密情報をログに出力しない
- 入力値を適切に検証する
- 将来的に認証と認可を導入できる構成にする

### NFR-05: 信頼性

OpenAI APIの失敗やタイムアウトに対応できること。

- エラー表示
- リトライ方針
- 入力内容の保持
- 生成中状態の管理

## MVPスコープ

MVPでは以下を実装対象とします。

- AI要件定義
- AIタスク分解
- 工数見積
- GitHub Issue形式Markdown生成
- AIレビュア
- AI業務改善提案
- 各機能の入力フォーム
- AI生成結果の表示
- Markdown形式の出力
- 基本的なエラーハンドリング

MVPでは以下を必須対象外とします。

- ユーザー認証
- 課金
- チーム管理
- GitHub APIによるIssue自動作成
- 高度な権限管理
- 本格的なSaaS運用

## 画面要件

### ホーム画面

各AI機能へ移動できること。

### AI要件定義画面

アイデアや課題を入力し、要件定義を生成できること。

### AIタスク分解画面

要件定義を入力し、タスク一覧、工数見積、優先順位を生成できること。

### GitHub Issue生成画面

AIタスク分解の結果から、GitHub Issue形式のMarkdownを生成できること。

### AIレビュア画面

コードや設計内容を入力し、レビュー結果を生成できること。

### AI業務改善提案画面

業務内容や課題を入力し、改善案を生成できること。

## 成功指標

初期段階の成功指標は以下です。

- 4つのAI機能が一通り利用できる
- AIタスク分解からGitHub Issue形式のMarkdownを生成できる
- タスクごとに工数見積と優先順位を確認できる
- ポートフォリオとして説明できる
- デモ環境で主要機能を試せる
- READMEとドキュメントからプロダクトの意図が伝わる
- 将来的なSaaS化に向けた拡張余地がある
