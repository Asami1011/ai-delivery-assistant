# Roadmap

## 方針

ai-delivery-assistant は、ポートフォリオとして見せられる完成度を早期に確保しながら、将来的なSaaS化に向けて段階的に機能を拡張します。

初期開発では、全機能を小さく動く形で実装することを優先します。その後、品質、UI、履歴管理、外部連携、チーム利用へ拡張します。

## Phase 0: 企画・設計

目的は、開発対象を明確にし、実装前の判断材料を整えることです。

- プロダクトビジョンの整理
- 主要機能の定義
- 初期ユーザー像の定義
- 画面構成の検討
- 技術スタックの選定
- MVP範囲の決定

完了条件:

- `docs/vision.md` が作成されている
- `docs/requirements.md` が作成されている
- MVPで実装する機能が決まっている

## Phase 1: MVP開発

目的は、4つのAI機能を最小構成で利用できる状態にすることです。

- AI要件定義機能
- AIタスク分解機能
- AIレビュア機能
- AI業務改善提案機能
- 入力フォームと結果表示画面
- Markdown形式での結果出力
- 基本的なエラーハンドリング

完了条件:

- 各機能に入力できる
- AI生成結果が画面に表示される
- 生成結果をMarkdownとして利用できる
- ポートフォリオとして動作デモが可能である

## Phase 2: 使いやすさと品質向上

目的は、実務利用に近い体験へ改善することです。

- UI/UX改善
- 入力テンプレート追加
- 生成結果の編集機能
- 生成履歴の保存
- 要件からタスクへの連携
- タスクからレビュー観点への連携
- テスト追加
- レスポンス速度と安定性の改善

完了条件:

- 過去の生成結果を確認できる
- 要件定義からタスク分解まで一貫して利用できる
- 主要機能にテストがある

## Phase 3: ポートフォリオ完成度向上

目的は、外部に見せられる成果物として完成度を高めることです。

- デモ用シナリオ作成
- README整備
- スクリーンショットや利用例の追加
- アーキテクチャ説明の追加
- デプロイ環境の整備
- サンプル入力とサンプル出力の用意

完了条件:

- READMEだけでプロダクト概要が理解できる
- デモ環境で主要機能を試せる
- 技術的な工夫を説明できる

## Phase 4: SaaS化準備

目的は、個人利用から複数ユーザー利用へ拡張するための土台を作ることです。

- ユーザー認証
- ワークスペース管理
- プロジェクト管理
- 生成履歴の永続化
- 利用量管理
- 権限管理
- 課金設計の検討
- セキュリティ設計

完了条件:

- ユーザーごとにデータを分離できる
- SaaSとして必要な基本設計が整理されている
- 課金や利用制限を追加できる構成になっている

## Phase 5: 外部連携・高度化

目的は、実際の開発業務や業務改善活動に組み込めるプロダクトへ発展させることです。

- GitHub連携
- Issue作成連携
- Pull Requestレビュー支援
- SlackまたはTeams通知
- JiraやNotionなどの外部ツール連携
- チーム向けテンプレート管理
- 組織単位のナレッジ蓄積

完了条件:

- 外部ツールと連携して作業成果を出力できる
- チーム利用を想定した運用が可能である

## 優先順位

初期の優先順位は以下です。

1. AI要件定義
2. AIタスク分解
3. AIレビュア
4. AI業務改善提案
5. 履歴保存
6. UI改善
7. 外部連携
8. SaaS化機能
